## Actual original sequence

Its `table-only.cjs` recursively freezes the literal table before constructing/owning the engine. `thermodynamics.cjs:ph` first checks finite numeric pressure/enthalpy and engine support. Internal energy is constructed downstream from enthalpy, pressure and density. Inside the engine, `ph(p,h)` calls `inverse(p,h,'h')`; `sat(p)` first checks positive pressure, logs pressure, checks log-table support, searches and interpolates saturation. The enthalpy band uses the original 1e-8 inclusive margins. Two-phase calls go directly to unchanged `statePX`, which calls saturation again. Otherwise kind/column/max are selected; liquid uses its existing branchLimit and inversion, untouched.

For vapor, the first `branch(p,max,kind)` checks the superheat offset axis BEFORE pressure positivity/log/domain/search, then interpolates three rows in the original nested order. Finally `statePT(p,a.T+(low+high)/2)` computes saturation AGAIN, chooses phase from temperature offset, calls branch, constructs p/T/h/s/rho/x/phase, and inverse overwrites h with target. Public engine PH has no extra finite/type validation and some invalid inputs can yield NaNs; preserve this behavior rather than invent successful finite states. ## Proposed exact transformation

Add an explicitly disabled-by-default factory option, enabled only by the B15 candidate table-only module after the existing deep freeze. Use a fresh local holder only for finite primitive numeric vapor PH inputs, after the original saturation/classification/liquid paths. Original raw factory callers, mutable custom tables, PS, PT, liquid and equilibrium PH keep the original path. A fourth internal branch parameter and fourth internal statePT parameter carry this holder. The first branch creates its pressure bracket at exactly the original expression, AFTER offset validation; later branches use that exact [index,weight]. The final statePT still computes its original saturation bracket and performs its original phase choice and offset validation before branch reuse. Keep saturation fully unchanged.

Only pressure index and weight are reused. All axis searches, nested mixRow operations, log-density interpolation, temperature construction, bisection arithmetic/comparisons and final property construction retain their exact order. No rounding, reassociation, pressure matching or quantization is introduced. The table is deeply frozen, p is a primitive constant throughout this invocation, and deterministic pBracket returns the same binary64 weight/index each time. Expected successful vapor PH: 40 branch calls and 38 bisections unchanged; pressure brackets 42 -> 3 (initial sat, first branch, final sat), NOT one total. Derive actual counts independently before claiming success.

The holder lives only in one inverse stack frame and its synchronous callees. It is never returned, attached to a result/table/engine/model/global, or retained by a closure. A throw discards it. Subsequent calls and different tables/instances cannot access it. Ordinary PH results remain fresh objects. At most one holder plus one pressure-bracket array per eligible call; eliminated bracket arrays are source-level construction counts, not measured allocator bytes.
