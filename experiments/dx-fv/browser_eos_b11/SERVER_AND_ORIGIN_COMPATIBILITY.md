# Server and origin compatibility

The copied standalone package passes root and nested-path serving in both actual desktop browsers, outside the repository. Strict local assets plus a same-origin CSP were tested; no historical path, /workspace path, CDN, external API or runtime model download is requested. Every source path/worker import resolves inside preview. Actual requests are retained in independent-server-requests.json and portability-{browser}.json. MIME types are explicit in the server handler and asset manifest; successful browser module loads verify MIME acceptance.

|---|---|---|

B10 requires crypto.randomUUID in the page/client and crypto.subtle.digest in the worker before bundle use. Loopback HTTP is potentially trustworthy; ordinary private-LAN HTTP is not. Workers/modules are not by themselves proof that the crypto-dependent backend will initialize. The separate origin-policy probe serves exact local package bytes through Playwright interception at a reserved .invalid HTTP origin, with unchanged CSP and browser security. It preserves original operation while A2 reports unqualified with a null snapshot. It performs no external network access and proves no LAN/server reachability. Direct private-address transport attempts are retained separately as HTTP 503 failures before app startup (private-origin-reachability.json and private-transport-*). No verification/UUID/security fallback was added.

Use same-origin module workers with correct JavaScript MIME; no CORS headers are required for same-origin assets and no SharedArrayBuffer/cross-origin isolation is used. HTTPS must be trusted on the actual device. Serve all files coherently, real missing-asset 404s and no HTML rewrite of module URLs. CSP tested: default-src self; script/style self + unsafe-inline for the original inline application; worker/connect self; img self + data; object none; base-uri self. No unsafe-eval needed. Exact header is in PREVIEW_HOSTING_HANDOFF.md.

The network must reach the server for any uncached asset, lazy module or new worker. A server with local assets can function without Internet, while browser offline mode may still block that local server. HTTPS on a disconnected network, a cached/service-worker PWA and native Files/Safari are distinct modes. Physical-device startup, memory, trust, backgrounding and touch remain untested.
