# B16 local Worker architecture

`index.html` → `app.mjs` / `suite.mjs` → `Client` → real module `Worker` → frozen bundle loader → original table factory and original coupled model. The local Python server uses JavaScript MIME types for `.mjs`. Nothing contacts Cloudflare. Scientific browser Web Workers and the owner's HTTPS Cloudflare Worker are different technologies.

The selectable control is exact B9C; candidate is exact corrected B15. Both fetch and verify the same-sized-class scientific assets, import a self-contained registry, create the original frozen owned table, use trace=true and failure-aware stepping, and run identical named configurations and targets. Module import plus loader/table construction are measured separately from asset fetch/hash verification. A prior cache-warming fetch is used identically for both. The benchmark does not claim empty browser cache startup.

B9D `worker.mjs`, `service.mjs`, `client.mjs` and `snapshot.mjs`, and the B10/B11 lifecycle contracts are design references. B16 copies the original compact snapshot projection unchanged, then annotates its source with the actual B15 variant/hash and B16 qualification. Scientific transport remains ordinary structured clone. B16 does not transplant a new solver or introduce an alternative property backend. The inherited projection's backend identifier describes the B9C family; B16 response/source fields identify the exact variant.

Commands carry protocol=1, session UUID, monotonic sequence, request ID, type and arguments. Each Worker owns one session and serializes requests. Named failure fixtures are explicitly test-only. B16 allows bounded ordered targets up to 0.01 s for research; this is not the workstation's accepted UI contract. Unknown commands and invalid envelopes return protocol failures. Original stop objects pass through without equipment-trip reinterpretation. Refusal returns no new fresh snapshot; prior display becomes stale. Stopped models cannot advance through the client. Detail diagnostics preserve the original stopped state and original record, including committed partial progress.

No command-response memoization is needed in this harness; a 128-command cap limits sessions. Model attempt history is capped at 256; snapshot histories are capped at eight. No continuously extended physical clock is allowed. Dispose drops model/table/record/history ownership before the client terminates the Worker. Restart makes a new UUID and model at time zero. Worker loss rejects pending work as external loss with unknown in-flight scientific result. Client rejects stale sequences, old accepted versions and cross-session responses. The minimal client is B16 research code, not a production replacement or a complete B9D retry contract.

Diagnostic Workers import the separately frozen B15 observer bundles. B16 attaches observation hooks without changing numerical source. Full residual result objects, coordinates, signed probe decisions, Jacobians, linear RHS/corrections, temporal objects, controller decisions and committed states/ledgers feed length-delimited exact binary64 SHA-256 streams. Count and digest equality are required. Incremental retention bounds diagnostic memory; hashing is excluded from primary timings. Primary Worker timing uses uninstrumented frozen bundles and compact snapshots. Full state/record/attempt digests are checked after timing.

The scientific gate and performance runner explicitly terminate Workers and close the browser. Outer process groups have wall/CPU bounds and a 512 MiB V8 heap option. The owner handoff is local-only and requires its own explicit future integration review before any workstation use.
