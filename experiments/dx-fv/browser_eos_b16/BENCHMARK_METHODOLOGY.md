# Benchmark methodology

Design commit `20406db` precedes harness implementation. Gate 0 verifies exact B15 and a clean initial tree, all historical bytes and sealed sources. The scientific gate must pass before `run-node.py` or primary browser performance/micro/retention campaigns start. Failed harness runs and their receipts remain in evidence. None is counted as a valid timing sample.

Primary cases use six pairs in AB/BA/BA/AB/AB/BA order, A=original, B=candidate. Each sample owns a fresh process or Worker. Fresh JIT (zero model warmups) and warmed JIT (two untimed bounded replays, followed by a fresh model) are separate strata. All solver timing uses the same trace=true, failure-aware options and original targets through 0.01 s. Each warmup is a reset simulation, not a horizon extension. Added/fine schedule pairs are supplemental and have smaller n. The last original interval from 0.005 to 0.01 s contains the warm phase transition and subsequent flow reversal; it is timed separately within compute.

PH input points are original supported pressures 3.5/3.65/4/6/12 bar absolute. Vapor enthalpy offsets are .00001/.1/5/50/150 kJ/kg above saturated vapor. Two-phase qualities are .1/.3/.5/.7/.9. Mixed alternates equal-count equilibrium and vapor inputs. Each class has 3,000 untimed calls followed by 20,000 timed calls. Every result checksum must match within a runtime. These are research workload classes, not installation duty-cycle distributions.

Report median paired percentages `(A-B)/A*100` and median paired milliseconds `A-B`. Neither is computed as a ratio/difference of group medians. Retain all samples, including timing extremes. Report medians, ranges and IQRs, pair count and faster-pair count. Small-sample descriptive statistics do not establish universal speedups or a real-device population confidence interval. Repeated workers/processes are independent sessions on one shared cloud host, not independent machines. Browser caching and host scheduling remain limitations.

Node reports process CPU and performance.now wall separately, including import/table/create scopes and coarse process memory. Chromium performance.now records wall time only. Solver compute surrounds original advances, including original record work. Service additionally includes validation/projection; client round trip includes dispatch and response delivery. Worker postMessage synchronous duration is reported in a following telemetry message. It includes synchronous clone/enqueue work but is not exclusive serialization CPU. Dispatch-to-worker and return-delivery use same-origin epoch timestamps and contain scheduling, queueing and clone-related work; timer precision can dominate very small values. Ping and compact snapshot echo characterize transport. `roundtrip-service` is only a residual wall-time envelope, never an exclusive clone or dispatch measurement.

Main-thread handler, textContent assignment and Worker projection are distinct. No renderer layout/paint measurement is claimed. The independent 10 ms heartbeat and timer-scheduled synthetic DOM input/tool clicks run through startup, warmup and accepted advance response. They stop before full diagnostic transfer/hash validation, pings and disposal, avoiding attributing deliberately expensive evidence hashing to solver responsiveness. Long Tasks observation is included where supported. This qualifies only the minimal harness on this host.

Counters-only variants, observer context probes, V8 trace-opt/deopt/inlining/GC and --jitless runs are separate sensitivity campaigns. Counters alter code shape and timing; profiler output adds overhead. No overlapping inclusive scope subtraction or lower-heap allocation-saving inference is allowed. GC events have timestamps and durations but may straddle scopes and be delivered later. Node heap/RSS and browser performance.memory are coarse observations, not allocation profiles or physical RAM attribution.

Each Node child has 65 s wall, 60 s CPU and 512 MiB heap limits. Browser suites have 600 s wall and inherited per-process 480 s CPU limits, plus Worker command deadlines, attempt/history caps and explicit teardown. Browser suites run sequentially with no simultaneous Node campaign. External termination is recorded separately from scientific refusal. Python/Node built-ins suffice except installed Playwright/browser automation; the owner ZIP needs Python standard library plus a browser.
