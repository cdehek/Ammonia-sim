# Next milestone recommendation

Select **Option C — Worker-first browser integration/performance research**, strictly isolated and **nonqualified**. Move experimental backend initialization and five-section physics execution into a dedicated worker harness; measure whole-model scheduling and error transport before deciding whether browser integration is practical. This is a recommendation only. B8 does not start it or authorize production integration.

The evidence supports this order: baseline accepted A2 uses a table engine; raw CoolProp DP is absent from its complete call graph; the unresolved full-VLE DU endpoints are configuration-specific and tied to boundary/reference obligations; C1 already demonstrates honest rejection/rollback without claiming phase recovery. A short original A2 trace and saved browser-supported C1 subset establish enough of the required PH/DU/SAT subset to define an isolated performance experiment. They do not establish full EOS-backed A2 qualification.

B7 observed maximum campaign main-thread heartbeat gaps of **1505.2 ms Chromium / 1775 ms desktop WebKit**, versus **76.8 / 94 ms** in worker campaigns. These are material operator-interface concerns, not causation evidence against Gate A and not whole-model worker qualification. An operator needs controls and alarms to remain responsive while refrigerant inventory, coil metal and finite air exchange heat. Moving work off the UI thread can be tested without making a new physical acceptance decision.

Do not extend boundary range, invent dry-suction behavior or rerun full A2 qualification. Freeze inputs and reporting times before measuring.

Require exact match where existing same-artifact behavior is exact. Any mismatch or invalid property acceptance fails the study; a worker must never turn a refusal into a usable state.
4. Replay the original supported/refused recovery sequence and C1 transient/persistent failures using the existing clearly labeled synthetic injection approach. Retain request bits, original native meaning, C1 classification, unproved trajectory-exit status, original floor/halving and exact rollback. Reuse proven exception lifecycle; explicitly serialize structured causes. Synthetic tests establish transport/handling, not natural reachability.
5. Measure cold module/factory initialization, first state, per-advance service time, input/output transfer cost, main-thread heartbeat distribution/maxima and worker memory/disposal. Run a small predeclared balanced set of matched rounds on actual Chromium and desktop WebKit. Show whether removing initialization and physics from the main thread materially reduces stalls. No patch-causality inference, arbitrary speedup claim or physical Safari/iPad claim. Failure to improve is an actionable result.
6. Deliver a worker/main-thread responsibility diagram, exact commands/results, failure transport schema, source/identity audit, and a go/no-go recommendation for further isolated browser research. Explicitly list remaining scientific qualification gaps and stop for review. Passing is a bounded architecture/performance result, never EOS/model/production qualification.

The experiment must retain a visibly nonqualified status and all original refusals. Do not introduce a pressure band, acceptance exemption, endpoint clipping, phase fallback or silent error swallowing to keep the worker running. It may compare an existing supported subset while preserving failed cases as errors; that is not a newly authorized runtime acceptance path.
